Callback Handler (server-side code)
import os, requests
from flask import request, session, redirect

SSO = os.environ['SSO_BASE_URL']

@app.route('/auth/callback')
def auth_callback():
    code = request.args.get('code')
    token = requests.post(f'{SSO}/oauth/token', data={
        'grant_type': 'authorization_code',
        'code': code,
        'redirect_uri': os.environ['SSO_REDIRECT_URI'],
        'client_id': os.environ['SSO_CLIENT_ID'],
        'client_secret': os.environ['SSO_CLIENT_SECRET'],
    }).json()['access_token']
    user = requests.get(f'{SSO}/oauth/userinfo',
        headers={'Authorization': f'Bearer {token}'}).json()
    # user = { id, username, name, email, email_verified, is_admin }
    session['user'] = user
    return redirect('/')
const SSO = process.env.SSO_BASE_URL;

app.get('/auth/callback', async (req, res) => {
  const { code } = req.query;
  const { access_token } = await fetch(`${SSO}/oauth/token`, {
    method: 'POST',
    body: new URLSearchParams({
      grant_type: 'authorization_code', code,
      redirect_uri: process.env.SSO_REDIRECT_URI,
      client_id: process.env.SSO_CLIENT_ID,
      client_secret: process.env.SSO_CLIENT_SECRET,
    })
  }).then(r => r.json());
  const user = await fetch(`${SSO}/oauth/userinfo`, {
    headers: { Authorization: `Bearer ${access_token}` }
  }).then(r => r.json());
  // user = { id, username, name, email, email_verified, is_admin }
  req.session.user = user;
  res.redirect('/');
});

Organization

Control your domain, registration rules, and account policies.

Domain
username@
All new accounts will get an email like username@{{ org.domain }}. No other email providers accepted.
Registration
New users will be inactive until an admin approves them in the Users panel.
What this does
  • When a user registers with username john, their email becomes john@{{ org.domain }} automatically — no input required.
  • Users cannot type a different email address — only your domain is accepted.
  • If you close registration, the sign-up page shows a notice and redirects to login.
  • If approval is required, new accounts are locked until you activate them in the Users panel.
